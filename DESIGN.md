# FINKI Hub Chat Design System

## 1. Purpose

The chat UI is an operational product surface: fast, quiet, and readable for students asking factual questions. New controls should preserve the existing sidebar rhythm rather than introduce a new visual language.

## 2. Tokens

- Color uses the existing Tailwind semantic tokens: `background`, `foreground`, `muted`, `muted-foreground`, `border`, `card`, `primary`, `destructive`, and `ring`. Positive persisted text and tinted states use `success`; `success-foreground` is reserved for text on solid success surfaces. Neutral optional states continue to use `muted`/`muted-foreground`. Light-theme focus indicators use an opaque `ring` color with at least 3:1 adjacent contrast, while destructive alert tints retain at least 4.5:1 text contrast.
- Spacing follows the existing 4px Tailwind scale. Sidebar row controls use `gap-1`, `px-2.5`, `py-1.5`, and icon padding `p-1`. The account trigger uses the same sidebar width with `gap-2`, `px-2`, and `py-2`. Auth cards use `p-6` on mobile and `p-8` on wider screens.
- Radius follows existing rounded surfaces: `rounded-md` for icon controls, `rounded-lg` for sidebar rows, `rounded-xl` for larger sidebar buttons, `rounded-2xl` for auth CTAs, and `rounded-3xl` for the auth panel.

## 3. Typography

- Sidebar rows use `text-sm`; section labels use `text-xs`, uppercase, and tracking-wide.
- Conversation titles are single-line, truncated, and left-aligned.
- Shared conversation messages use pretty wrapping to avoid orphaning short words and may break unbroken URLs, hashes, or tokens anywhere rather than clip them on narrow screens.
- Auth copy leads with the student task and concrete study value, not authentication mechanics or server terminology. The sign-in surface carries one question-form headline plus one supporting sentence — no benefit lists or badge elements. Keep the auth headline balanced at `text-4xl` and `sm:text-5xl`.

## 4. Motion

- Motion is limited to explicitly named color, shadow, opacity, grid-row, and transform transitions. Broad `transition-all` is not used.
- Loading indicators may rotate, but only to communicate an in-progress action.

## 5. Components

- Sidebar conversation row: full-row selection button spanning the rounded hover surface, with compact row-action icon buttons layered above it and independently operable on fine pointers. Coarse pointers use one 44px overflow trigger with labeled generate, rename, and delete menu items so conversation titles keep useful width.
- Row action button: Lucide icon, `size-3.5`, semantic aria label, focus-visible ring, muted default color, stronger hover color matching the action intent, and the existing Radix tooltip using the same localized label on hover or keyboard focus.
- Destructive row action: use destructive hover color only for delete.
- Answer sources: automatically expose one or two source cards below a completed answer; larger source sets stay collapsed behind the source-count trigger. Snippets use the shared Markdown renderer in both collapsed previews and expanded content, suppress remote images, and keep inline Markdown links non-interactive until the card expands. The trigger and external source links keep compact fine-pointer sizing and expose at least 44px targets on coarse pointers.
- Auth sign-in layout: a two-column grid from `lg` — brand row, headline, supporting line, and provider actions on the left; the chat showcase on the right. Below `lg` the columns stack with the actions before the showcase. Provider buttons are `rounded-2xl` `card` surfaces that visibly change border/background on hover, use `focus-visible:ring-ring`, and follow `Продолжи со {provider.name}`; the sign-in error alert and the providers-unavailable notice render directly above the actions in the same column. The real brand mark (`/logo.png`) identifies the page — no generic icons. Vertical page padding keeps its standard spacing as a minimum and yields to larger device safe-area insets.
- Auth chat showcase: a decorative, self-playing conversation window (`aria-hidden`, `pointer-events-none`, nothing focusable) built from the real message idioms — user bubbles on `secondary`, plain assistant text, and source cards with `прашање`/`документ` type chips. On `lg` it absolute-fills a stretched grid item so its height always equals the left column's natural height; below `lg` it uses a fixed `26rem`. The loop reserves the typing indicator's slot in the same beat as the question so the dots never scroll the thread, parks whenever the tab is hidden so exchanges cannot queue up in the background, reshuffles exchange order every cycle, and renders a single static exchange under `prefers-reduced-motion`. Inline link-styled text uses Streamdown's link classes (`font-medium text-primary underline`) but stays inert.
- Credential settings dialog: modal card using existing `Dialog`, `Input`, and `Button` primitives. Its header and action footer remain fixed while the provider list is the sole vertical scroll owner inside the dynamic viewport bound. Save failures remain visible in the fixed action area at normal heights, group affected providers by failure kind, and are programmatically associated with the corresponding API-key or Base URL field. At viewport heights of `30rem` or less, the failure summary joins the provider scroll body and the actions use one compact row so both controls remain fully accessible without introducing a second scroll owner. Credential saves and deletes are serialized per authenticated session across dialog closure, responsive transitions, and component remounts. Closing the dialog restores focus to the connected control that opened it, or to the persistent header sidebar trigger if a responsive transition removed that control. The footer uses `background` plus `border-t`, stacks full-width actions on narrow screens in the same order as keyboard navigation, becomes a right-aligned row from `sm` or when the viewport is exceptionally short, and never obscures provider content. Provider rows use `border`, `card`, `muted`, and `muted-foreground` tokens, with an official API-key dashboard link in the top-right action group and a quiet ghost-style delete action only when a credential exists. External links use a Lucide icon, visible localized text from `sm` upward, a provider-specific accessible name at every width, safe new-tab attributes, and a 44px coarse-pointer target; narrow mobile keeps the icon-only presentation so card actions do not overflow. Deleting a saved key opens a focused confirmation dialog; cancellation preserves the credential and confirmation is the only path that starts deletion.
- Credential provider status: place a compact text-and-icon status beside each provider heading. A persisted key uses `success`/`success-foreground` and the visible label `Зачувано`; a provider without a key uses the neutral `muted`/`muted-foreground` treatment and the visible label `Опционално`. Status never relies on color or icon shape alone. Errors remain destructive alerts, and pending actions retain `aria-busy` plus the existing spinner convention.
- Credential fields: every input has a visible `<label>` associated by `htmlFor`/`id` while retaining a provider-specific accessible name. The API-key description tells users whether entry adds an optional key or replaces a saved one and uses pretty wrapping to avoid orphaned Macedonian words. The Base URL is visibly optional and uses `aria-describedby` to expose the guidance that an empty value selects the provider default; the placeholder is an example or current endpoint, never the only explanation.
- Dialog geometry: shared modal content centers within the safe viewport rectangle and keeps a standard 16px gutter inside every active safe-area inset. A specialized dialog may replace the shared content scroller with a documented `scroll-body-shell`, but it inherits the shared safe-area width and height bounds so no fixed region or overflowing content enters a display cutout.
- Model selector option: group models only by provider in catalog order. Models without saved provider credentials remain visible but disabled, use `muted-foreground`, and pair a Lucide key icon with visible key-required text rather than relying on color or hover help.
- Scrollable select menu: keep both scroll-arrow rows mounted while overflow exists so reaching a boundary never moves the popup. Show the unavailable direction with `muted-foreground` and without pointer behavior; hide both rows when the menu does not overflow. The catalog may remain scrollable at a 1280×900 viewport as its fixed allowlist grows, and the final option must remain reachable through the select viewport rather than expanding the popup beyond its collision bounds.
- Diagnostics hover card: preserve the existing hover/focus interaction, keep the card inside the dynamic viewport with the standard 16px outer gutter, and make the card the single vertical scroll owner when its full diagnostics content is taller than the available screen. The preferred minimum width must yield to Radix's available width on ultra-narrow viewports. While the trigger has keyboard focus, Arrow, Page Up/Down, Home, and End keys scroll the card without moving the conversation. Desktop-sized content remains unchanged and the surrounding conversation does not become a second scroll owner.
- Compact sidebar: viewports below `lg` use a modal Radix dialog that traps focus, closes on Escape or overlay interaction, and restores focus to the header trigger. Desktop viewports from `lg` retain the static complementary landmark so tablet-width chat content keeps enough reading space.
- Conversation loading state: preserve the current list/thread during transient failures and present an inline alert with a retry action. Only a confirmed missing conversation clears the selection.
- Composer submission failure: retain the draft and show an inline retryable error; clear the draft only after the message is accepted.
- Mobile composer layout: reserve the bottom safe-area inset around the composer. On viewports no taller than `500px`, keep the full disclaimer available to assistive technology but visually clamp it to one line and reduce the conversation context bar to a 44px control row so the message thread retains a practical reading area.
- Sponsored quota notice: present the exhausted state and localized reset time as passive information, then offer `Додај API клуч` as the only recovery action. Use the existing primary `Button` treatment with a coarse-pointer 44px target. Do not render wait, dismiss, or retry controls that cannot change the quota state.
- Sidebar account trigger: a full-width bottom-left button that keeps the user name and email readable, truncates long identity text, and opens upward. It uses the existing `background`, `foreground`, `muted`, `border`, and `ring` tokens with a compact hover/focus surface rather than a separate card.
- Sidebar account menu: an existing Radix `DropdownMenu` aligned to at least the trigger width and allowed to expand enough to keep action labels on one line. It groups the API-key action above a separator and keeps the destructive clear-history and sign-out actions below it. The clear-history item is shown only when conversations exist, names its all-conversations scope explicitly, and opens the existing confirmation dialog before deletion. On mobile, selecting API keys closes the sidebar drawer before opening credential settings.
- Conversation context bar: a slim, non-scrolling row inside the main conversation region, directly above the message scroller. It shows the active conversation title on the left and the existing share controls on the right. It uses `background`, `border`, `foreground`, and `muted-foreground` tokens without adding a second elevated card surface.
- Conversation share action: an `IconButton` inside the conversation context bar using the existing control tokens and Lucide icons. The bar is omitted when there is no active conversation; sharing preserves distinct pending, copied, failed, and revoke states without adding a toast system. An already-shared conversation restores its server-owned share link after reload, so copy-link and unshare controls remain available until revocation succeeds.
- Header control tooltip: compact header actions reuse the existing Radix `Tooltip` primitive below the control with a 4px offset. Tooltip copy matches the localized accessible name, updates with action state, opens on hover or keyboard focus, and remains hoverable for disabled controls through the documented wrapper pattern.
- Skip navigation: the root layout exposes a localized skip link as the first focusable control. It stays visually hidden until keyboard focus and targets the stable `main-content` landmark on authenticated, shared, and sign-in surfaces.
- Shared conversation view: a read-only shell with the standard border/background header, brand mark, conversation title, and existing thread renderer. It omits sidebar, composer, credentials, feedback, and regeneration controls.

## 6. Accessibility

- Every icon-only action must have an `aria-label` from `web/lib/i18n.ts`.
- Primary controls, dialog actions, close controls, search clear, conversation overflow actions, source disclosure, and external source links expose at least 44px targets whenever the primary pointer is coarse. Compact desktop sizing is gated by `pointer-fine`, not viewport width, so touch tablets retain full targets.
- Mobile header, drawer, skip link, sign-in content, and portaled dialogs honor safe-area insets on every edge; decorative logo and GitHub shortcut are hidden below `sm` to protect the title and primary actions.
- Modal drawers contain keyboard focus and restore it to their invoking control.
- The account trigger exposes its expanded state through the Radix menu primitive, retains a visible focus ring, and keeps identity text available through a full accessible label when visual text truncates.
- The account menu uses keyboard-navigable menu items, gives the sign-out item destructive text treatment, and does not rely on color alone because both actions retain visible labels and icons.
- The main shell keeps a single message-scroll owner: the global header, conversation context bar, sidebar footer, and composer remain fixed while the thread scrolls.
- Disabled async actions must expose `aria-busy` when work is pending.
- Non-error credential statuses remain readable without color, and helper copy is programmatically associated with its input through `aria-describedby`.
- Destructive credential and conversation actions require explicit confirmation before the request starts, retain recoverable context after failure, and prevent duplicate submissions while pending.
- Share-state changes must update the icon button's localized accessible name so copied and failed outcomes are available without relying on color.
- Auth failures must use `role="alert"` and include a direct recovery step. Missing provider configuration must be described as temporary unavailability without exposing server terminology.
